# 🧠 エンジニア向けドキュメント学習支援アプリ 要件定義書

## 1. 概要

### アプリ名（仮）

**Recall(リコール)**

### 概要説明

エンジニアが日々読む公式ドキュメントや技術記事（Zenn・Qiita・Mediumなど）を、
リーディングリストとして保存・整理し、各記事にMarkdownでメモを残せるアプリ。
さらに、保存した記事やメモ内容をもとにAIが自動で復習問題を生成し、学習内容の定着を支援する。

### 目的

- 学習記事を「読むだけ」で終わらせず、知識を整理・定着させる
- Markdownでの記録とAI復習を一体化
- エンジニアの学習効率を最大化する

### 想定ユーザー

- 学習中の学生エンジニア
- 若手エンジニア・キャリア初期層
- 日々ドキュメントや記事を読む実務エンジニア

### 提供価値

- 技術記事を保存し、メモと共に体系的に学べる
- AIによる復習で理解度を測定・強化できる
- 自分だけの「技術知識ベース」を構築可能

## 2. システム構成

| 項目           | 技術・サービス                                       |
| -------------- | ---------------------------------------------------- |
| フロントエンド | React（Next.js）または Expo（React Native）          |
| API形式        | GraphQL                                              |
| バックエンド   | AWS Lambda（Go製 GraphQL API）                       |
| API管理        | AWS API Gateway                                      |
| 認証           | Supabase Auth（SSO対応：Google / GitHub / LINE / X） |
| データベース   | Supabase PostgreSQL                                  |
| ストレージ     | Amazon S3（OGPキャッシュ・画像アップロード等）       |
| AI連携         | OpenAI API（問題生成）                               |
| デプロイ       | AWS SAM / Serverless Framework                       |
| CDN            | CloudFront（Web対応時）                              |

---

## 3. 機能要件

### 3.1 認証・ユーザー管理

- Supabase Authによるサインイン / ログアウト
- Google・GitHub・LINE・XのSSO対応
- プロフィール設定（名前・アイコン）
- AI用OpenAI APIキーの登録・管理（1ユーザー1キー）

### 3.2 記事管理（リーディングリスト）

- URL入力による記事登録（OGP自動取得 → S3にキャッシュ保存）
- タグ・カテゴリ付与
- 一覧表示（軽量版・詳細版）
- 検索・フィルタリング（タグ・既読・更新順）
- 削除・編集機能

### 3.3 メモ機能（Markdown対応）

- 記事ごとに複数メモ作成・編集・削除
- メモにタイトル必須
- Markdownプレビュー表示
- 更新日時の自動管理
- 添付画像のS3アップロード対応

### 3.4 AI復習問題生成

- メモ内容を元にAIが自動で問題を生成（OpenAI API）
- 問題の再生成・履歴保存
- 問題形式：正誤 / 選択式 / 記述式
- 詳細画面で生成ボタン・編集可能

### 3.5 タグ管理

- タグの追加・編集・削除
- タグ名・カラー設定
- 記事・メモに付与可能

### 3.6 検索・フィルタリング

- タイトル・URL・タグ・メモ内容検索
- 登録順・更新順ソート
- 未読・既読フィルタ

### 3.7 設定関連

- プロフィール設定画面（名前・アイコン）
- AI APIキー管理画面（OpenAI APIキー、1ユーザー1キー）
- テーマ設定画面（ライトモード / ダークモード）
- アカウント連携画面（Google / GitHub / LINE / X）

| テーマ設定         | ライト/ダークモード切替                        |
| アカウント連携     | Google / GitHub / LINE / Xの連携状況管理       |

## 5. 非機能要件

| 項目           | 内容                                          |
| -------------- | --------------------------------------------- |
| パフォーマンス | Lambdaのコールドスタートを抑制（Go採用）      |
| セキュリティ   | Supabase Auth JWT検証 / S3 Pre-signed URL運用 |
| 可用性         | サーバーレス構成により自動スケーリング        |
| 保守性         | GraphQLスキーマ駆動設計による変更容易性       |
| 拡張性         | 将来的なWeb＋モバイル両対応を想定             |

## 6. データ要件（概要）

| エンティティ | 主な項目                                                                      |
| ------------ | ----------------------------------------------------------------------------- |
| User         | id, name, email, avatar_url, created_at                                       |
| UserProvider | id, user_id, provider (Google/GitHub/LINE/X), provider_id, created_at         |
| Article      | id, user_id, url, title, og_image_url, tags, created_at, updated_at           |
| Memo         | id, article_id, title, content, created_at, updated_at                        |
| Quiz         | id, article_id, question, answer, type (true/false, choice, text), created_at |
| Tag          | id, name, color                                                               |
| ApiKey       | id, user_id, key, created_at                                                  |
